# Needless UI

Open-source UI component library ("Needlessly Engineered Styling Toolkit"). Angular first, React later. MIT.

## Public repository: no leaks

This repository is public, and anything pushed stays public. Before every commit, review the staged files and diff. Never commit secrets or tokens, personal data, machine-specific paths, local tool files (`.claude/settings.local.json`, reports, scratch files) or build output. Strip image metadata (EXIF, XMP, C2PA) unless it's meant to be published. Commit with the maintainer's chosen identity, never a machine's global one. When in doubt, ask before pushing.

## Layout

- `packages/tokens`: W3C DTCG 2025.10 token sources in `src/`, compiled by our own compiler (`scripts/lib.ts`) to `dist/tokens.css` + `dist/tokens.json`. Color scales are generated by `scripts/palette.ts`; never hand-edit `src/color/*.tokens.json`.
- `packages/css`: framework-free component CSS, one file per component in `src/components/`, all inside `@layer nui.*`. Bundled by lightningcss (`scripts/bundle.ts`).
- `packages/angular`: `@needless-ui/angular`, built with ng-packagr. One secondary entry point per component (`button/`, `toast/`, `number-field/`, …); shared types, `NuiPersonality`, `springTransition()`, placement (`nuiFollow`), `NuiVirtualizer`, fuzzy search and shortcuts in `src/`. Form controls implement `ControlValueAccessor`, which Signal Forms' `[formField]`, reactive forms and `ngModel` all use.
- `apps/docs`: the documentation site (www.needlessui.com, deployed by Vercel from `main` per `vercel.json`), prerendered to static HTML with `outputMode: 'static'` in 30 languages (the most spoken): English at the root, the others under their id (`/it`, `/zh-hans`, `/ar`; list in `i18n/locales.ts`). Its tsconfig is `tsconfig.docs.json` at the workspace root on purpose: from `apps/docs`, Angular silently drops the route `modulepreload` hints (it matches routes to chunks by paths relative to the tsconfig).
- `specs/`: framework-agnostic contract per component (API, states, keyboard, a11y). Implementations follow it.

## Commands

- `pnpm dev`: build tokens, serve the docs site
- `pnpm build`: tokens → css → Angular package (`dist/needless-ui/angular`)
- `pnpm test`: node:test suites for tokens and css, Vitest for Angular
- `pnpm typecheck`, `pnpm format`, `pnpm format:check`
- `pnpm build:docs`: prerenders the docs site (catches SSR bugs), then `apps/docs/scripts/seo-check.ts` fails on any SEO problem and writes `sitemap.xml` plus a `<page>.html` twin of every page (static hosts serve `/a/b` from `a/b.html` without a trailing-slash redirect; the `/404` twin is the host's `404.html`), `paint-first.ts` makes pages paint before hydrating (main.js is modulepreloaded and imported after the first contentful paint), and `trim-css.ts` drops unread custom properties from each page's inline CSS.
- `pnpm check:browsers` (after `pnpm build:docs`): every component page in Chromium, Firefox and WebKit, on a computer and a touch screen; run it before releases.
- Scripts in `packages/*/scripts` are TypeScript run directly by Node (type stripping): erasable syntax only, `.ts` import extensions.

## Conventions

- Prefix `nui` everywhere: selectors `nui-*` / `[nui*]`, classes `.nui-*`, custom properties `--nui-*`, layers `nui.*`.
- Angular components never ship styles. They set classes and `data-*` attributes that `@needless-ui/css` targets. Prefer directives on native elements over wrapper components.
- Component CSS uses only semantic tokens (`--nui-color-bg-*`, `--nui-color-<tone>-*`, …), never numbered scales. A test enforces that referenced tokens exist.
- Build behavior on native elements, `@angular/aria` and `@angular/cdk`; don't reimplement keyboard/ARIA logic.
- New component = spec + CSS + Angular entry point + tests + docs page (id in `docs/ids.ts`, API and examples in `docs/registry.ts`, words in every `i18n/messages/<locale>.ts`) + changeset (`pnpm changeset`).
- All `@needless-ui/*` packages are versioned together (Changesets `fixed`).
- Angular unit tests run in headless Chromium, Firefox and WebKit (Vitest browser mode, `@vitest/browser-playwright`); drive input with `userEvent` from `vitest/browser`. jsdom has no `<dialog>` or popover support.
- Component pages load their words from `components.items.<id>`; decorative card previews render in the browser (`@defer`), so the components page stays inside the first network round trip. Keep every prerendered page under about 14 KB compressed (brotli level 5): above that, Lighthouse's first contentful paint needs a second round trip.
- Docs weight: each example is its own chunk (`load` in `docs/registry.ts`), loaded for its page by `examplesResolver` before the page renders, so hydration finds it. Heavy examples set `defer` (a placeholder height) and render in the browser near the viewport. Example sources load on “Show code” (`generated/examples-code.ts`); only snippets ship with pages. After the build, `scripts/trim-css.ts` drops custom properties the inline critical CSS never reads. Bind message HTML with `| trusted` (our own static text), so hydration doesn't sanitize every paragraph again.
- Docs i18n: typed message modules per locale (`i18n/messages/<id>.ts`, shape in `types.ts`, `en.ts` is the source). Each language is its own lazy chunk: the app initializer loads the first page's language, and the `loadLocale` guard on every page route loads the next one. Read words through `I18n.t()`. Site links inside message html carry no language prefix; `I18n` adds it on load. Arabic, Urdu and Persian render `dir="rtl"`, so use logical CSS properties only. A text change in `en.ts` must reach all 29 translations.
- Docs easter egg: `layout/emergency.ts` is the DO NOT PRESS button on every page; pressing it imports `layout/gravity.ts` (matter-js, a lazy chunk) and the visible page falls under physics until reload. Blocks move only by CSS transform, so they stay clickable and accessible; reduced motion keeps it off.
- Docs SEO: every page calls `Seo.set()`; titles ≤ 70 wide, descriptions 50–160 wide (measured by `scripts/text-width.ts`: CJK counts double), unique within each language. The 404 page is `noindex`.
- Customization: `packages/css/src/presets.css` maps `data-nui-*` attributes to inherited custom properties (`--nui-motion`, `--nui-press`, `--nui-enter`, `--nui-corner-shape`, `--nui-radius-scale`, `--nui-density`); components only read them. Entrances and presses spring on `--nui-motion`; exits never do (a closing dialog stays in the top layer until its transition ends). Under reduced motion, components ignore the press and entrance transforms. Angular inputs come from the `NuiPersonality` host directive. Spec: `specs/customization.md`.
- Spring tokens are DTCG `transition`s with the physics in `$extensions["com.needlessui.spring"]` and a cubic-bezier stand-in as `$value`. `springToCss` (tokens compiler) and `springTransition` (`packages/angular/src/spring.ts`) are twins; a tokens test keeps their output identical.
- The data grid (`grid/`) keeps its model in `NuiGridEngine` (filter, sort, page, selection, column state, active cell) and moves focus through the data, not the DOM, so it virtualizes; Angular Aria's grid only knows rendered cells. Its state lives in models (`sort`, `filters`, `search`, `page`, `selected`, `columnState`).
- Pickers (select, combobox, command palette) share `NuiOptionEngine` (the model: fuzzy search, groups, trees, active row) and `nui-option-list` (the listbox, virtualized past 200 rows) from `select/`. Focus stays in the field and points at the active option with `aria-activedescendant`, so the active row must stay rendered. Lists render only while open: a closed picker is one element in the prerendered page.
- Phone numbers: the calling codes, groupings and trunk prefixes in `packages/angular/phone-field/src/countries.ts` are hand-written facts (ITU assignments, national numbering plans). Don't copy libphonenumber's metadata (Apache-2.0) into the repo; apps that need full validation can use it themselves.
- Color: the color picker works in OKLCH, and its math (`color-picker/src/color.ts`: CSS Color 4 parsing, conversions, gamut mapping, WCAG contrast) has no dependencies. The picker's area paints a canvas in the browser only.
- Angular Aria menus report every choice through the root menu's `itemSelected` (never submenus), and they pick the item to focus before our popover is visible. `NuiMenu`/`NuiMenuItem` compensate; keep that in mind when wrapping other Aria patterns.
- Text from outside (Markdown, chat replies) is parsed into a tree and rendered with templates, never `innerHTML`; links must pass `nuiSafeUrl`. A chat conversation is a tree of messages (`parent`); `NuiChatSession.messages()` is the branch on screen, `all()` every version.
- The rich text editor (`editor/`) keeps an immutable document (blocks with stable ids, text runs with marks) and makes every edit from `beforeinput`; only IME compositions are read back from the DOM. Pasted HTML is parsed in an inert `<template>` and links must pass `nuiEditorSafeUrl`.
- Every page also renders on the server, where views are destroyed after rendering and the DOM is Domino's: guard browser APIs even in destroy hooks (`if (this.frame) cancelAnimationFrame(this.frame)`), and use `setAttribute`, `appendChild` and `removeChild` (Domino has no `dataset`, `replaceChildren` or `append`). Unit tests run in a real browser and miss this; load the page through `pnpm dev` or run `pnpm build:docs`.
- Browsers: Chrome and Edge 120, Firefox 125, Safari and iOS 17 (`specs/browser-support.md`; the CSS bundle's targets match). Angular tests run in Chromium, Firefox and WebKit, one test file at a time (Firefox gives focus to one page at a time). Safari doesn't focus the buttons it clicks: a trigger whose keys matter after a click focuses itself. Tests must not rely on one engine: synthetic `ClipboardEvent`s need `clipboardData` defined on the event (Firefox ignores the constructor's), Home and End don't move the caret on Apple platforms, and Safari's Tab skips buttons and links. In a popup sized by its content, a scrolling flex child takes `flex: 1 1 auto`: Safari 17 gives `flex: 1` (a 0% basis) no height there. Only a real Safari on iOS 17 shows that; check popups in the Xcode simulator.
- Touch: drags use pointer events with `touch-action` and abort on `pointercancel`; a drag that competes with page scrolling starts on a long press (the scheduler). Text from input methods (every word on Android keyboards) can't be refused in `beforeinput`: read it on `compositionend`. Fields get at least 16px on `(pointer: coarse)`, or iOS zooms into them. Hover only ever adds.
- The docs site's `docs` layer beats component styles, so its element selectors must stay scoped: tables in `.table-wrap`, example paragraphs outside `.nui-markdown` and `.nui-chat`.

## Angular guidelines (generated by the Angular CLI)

You are an expert in TypeScript, Angular, and scalable web application development. You write functional, maintainable, performant, and accessible code following Angular and TypeScript best practices.

## TypeScript Best Practices

- Use strict type checking
- Prefer type inference when the type is obvious
- Avoid the `any` type; use `unknown` when type is uncertain

## Angular Best Practices

- Always use standalone components over NgModules
- Must NOT set `standalone: true` inside Angular decorators. It's the default in Angular v20+.
- Do NOT set `changeDetection: ChangeDetectionStrategy.OnPush` explicitly. `OnPush` is the default in Angular v22+.
- Use signals for state management
- Implement lazy loading for feature routes
- Do NOT use the `@HostBinding` and `@HostListener` decorators. Put host bindings inside the `host` object of the `@Component` or `@Directive` decorator instead
- Use `NgOptimizedImage` for all static images.
  - `NgOptimizedImage` does not work for inline base64 images.

## Accessibility Requirements

- It MUST pass all AXE checks.
- It MUST follow all WCAG AA minimums, including focus management, color contrast, and ARIA attributes.

### Components

- Keep components small and focused on a single responsibility
- Use `input()` and `output()` functions instead of decorators
- Use `model()` for two-way bound properties with `[(prop)]` syntax instead of pairing `input()` with `output()`
- Use `computed()` for derived state
- Use `linkedSignal()` for state derived from multiple reactive sources that must stay synchronized
- Prefer inline templates for small components
- Prefer Signal Forms (`@angular/forms/signals`) for new forms. They are stable in Angular v22+ and provide signal-based state, type-safe field access, and schema-based validation
- When not using Signal Forms, prefer Reactive forms instead of Template-driven ones
- Do NOT use `ngClass`, use `class` bindings instead
- Do NOT use `ngStyle`, use `style` bindings instead
- Do NOT import `CommonModule`, import only the directives and pipes the template uses, such as `AsyncPipe` or `DatePipe`
- When using external templates/styles, use paths relative to the component TS file.

## State Management

- Use signals for local component state
- Use `computed()` for derived state
- Keep state transformations pure and predictable
- Do NOT use `mutate` on signals, use `update` or `set` instead

## Templates

- Keep templates simple and avoid complex logic
- Use native control flow (`@if`, `@for`, `@switch`) instead of `*ngIf`, `*ngFor`, `*ngSwitch`
- Use the async pipe to handle observables
- Do not assume globals like (`new Date()`) are available.

## Services

- Design services around a single responsibility
- Use the `providedIn: 'root'` option for singleton services
- Prefer the `@Service` decorator over `@Injectable({providedIn: 'root'})` for new singleton services (Angular v22+)
- Use the `inject()` function instead of constructor injection
